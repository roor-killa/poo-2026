# Les 4 notions clés des méthodes spéciales en Python

## 1. Dunder methods et `__init__`

Les dunder methods (double underscore methods), également appelées méthodes magiques ou méthodes spéciales, sont des méthodes avec des noms entourés de double underscores qui permettent aux classes Python de définir comment elles interagissent avec les opérateurs et fonctions intégrées du langage. La méthode `__init__` est le constructeur d'instance le plus couramment utilisé, appelée automatiquement lors de la création d'un objet pour initialiser ses attributs avec les paramètres fournis. Contrairement aux langages comme Java ou C++, `__init__` n'est pas un vrai constructeur mais un initialiseur : l'objet existe déjà (créé par `__new__`) avant l'appel d'`__init__`. Ces méthodes spéciales constituent le protocole d'interface de Python, permettant aux objets personnalisés de se comporter comme des types natifs et de s'intégrer naturellement avec la syntaxe du langage. Elles sont invoquées implicitement par l'interpréteur et ne doivent généralement jamais être appelées directement (sauf via `super()`), garantissant une séparation nette entre l'interface publique et le mécanisme interne.

## 2. `__str__` et `__repr__` (méthodes de représentation)

Les méthodes `__str__` et `__repr__` définissent comment un objet est converti en chaîne de caractères, mais avec des objectifs distincts et complémentaires. `__str__` produit une représentation "lisible" destinée à l'utilisateur final, invoquée par `str(obj)` et `print(obj)`, privilégiant la clarté et la concision pour l'affichage. `__repr__`, quant à elle, vise une représentation "non-ambiguë" destinée aux développeurs, idéalement capable de recréer l'objet via `eval(repr(obj))`, invoquée dans la console interactive et par `repr(obj)`. La convention veut que `__repr__` ressemble à une expression Python valide (comme `Point(x=3, y=5)`) tandis que `__str__` peut être plus libre (comme `"Point at (3, 5)"`). Si seul `__repr__` est défini, il sert également de fallback pour `__str__`, mais l'inverse n'est pas vrai. Ces deux méthodes sont essentielles pour le débogage, le logging et la création d'APIs intuitives, transformant des objets opaques en informations exploitables.

## 3. Surcharge d'opérateurs

La surcharge d'opérateurs permet de redéfinir le comportement des opérateurs Python (`+`, `-`, `*`, `==`, `<`, etc.) pour vos classes personnalisées en implémentant les méthodes dunder correspondantes (`__add__`, `__sub__`, `__mul__`, `__eq__`, `__lt__`, etc.). Cette fonctionnalité rend le code plus expressif et naturel : au lieu d'écrire `vector1.add(vector2)`, vous pouvez écrire `vector1 + vector2`, alignant vos objets avec la syntaxe intuitive des types natifs. Python distingue les opérateurs normaux (`__add__`) et réfléchis (`__radd__`), ces derniers étant appelés lorsque l'opérande de gauche ne supporte pas l'opération, permettant une commutativité flexible. Les opérateurs d'augmentation (`+=`, `-=`) ont leurs propres méthodes (`__iadd__`, `__isub__`) qui peuvent modifier l'objet en place pour les types mutables ou retourner un nouvel objet pour les immuables. Il est crucial de respecter les conventions mathématiques et le principe de moindre surprise : `==` doit être symétrique, `<` doit être transitif, et les opérateurs arithmétiques doivent retourner de nouvelles instances plutôt que modifier l'objet en place.

## 4. `__len__`, `__getitem__`, `__contains__` (protocole de conteneur)

Ces trois méthodes constituent le protocole de conteneur qui permet à vos objets de se comporter comme des collections natives Python. `__len__` définit le comportement de `len(obj)` et doit retourner un entier non-négatif représentant la taille du conteneur, rendant vos objets compatibles avec les tests de vérité booléenne (un conteneur vide est `False`). `__getitem__` implémente l'accès par index ou clé avec la syntaxe `obj[key]`, supportant les entiers pour les séquences, les slices pour le découpage, ou n'importe quel type hashable pour les mappings, rendant également l'objet itérable automatiquement. `__contains__` définit le comportement de l'opérateur `in` via `item in obj`, avec un fallback automatique sur `__getitem__` si absent, mais une implémentation explicite peut être plus efficace (O(1) pour un set vs O(n) pour une liste). Implémenter ces trois méthodes transforme votre classe en un conteneur Pythonique à part entière, compatible avec les fonctions natives, les compréhensions, et les idiomes standard du langage, tout en bénéficiant du duck typing pour l'interopérabilité maximale.
