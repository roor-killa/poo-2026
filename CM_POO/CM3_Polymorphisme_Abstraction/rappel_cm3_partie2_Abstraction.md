# Les 4 notions clés de l'abstraction en Python

## 1. Module abc (Abstract Base Classes)

Le module abc (Abstract Base Classes) est le mécanisme standard de Python pour créer des classes abstraites qui servent de modèles ou de contrats pour d'autres classes. Il fournit la métaclasse ABCMeta et le décorateur @abstractmethod permettant de définir des méthodes qui doivent obligatoirement être implémentées par les classes dérivées. Une classe abstraite héritant de ABC (ou utilisant ABCMeta comme métaclasse) ne peut pas être instanciée directement : toute tentative lève une TypeError si des méthodes abstraites ne sont pas implémentées. Ce module permet également de définir des propriétés abstraites avec @property et @abstractmethod combinés, et des méthodes de classe abstraites avec @classmethod et @abstractmethod. L'utilisation d'abc apporte une validation au moment de l'instanciation plutôt qu'à l'exécution, détectant les implémentations incomplètes avant même que le code problématique soit exécuté.

## 2. @abstractmethod

Le décorateur @abstractmethod marque explicitement une méthode comme abstraite, signalant qu'elle doit être redéfinie dans toute classe concrète dérivée. Lorsqu'une classe contient au moins une méthode abstraite, elle devient automatiquement non-instanciable et force ses sous-classes à fournir une implémentation concrète de toutes les méthodes abstraites héritées. Ce décorateur peut être combiné avec d'autres décorateurs Python comme @property, @classmethod ou @staticmethod, mais doit toujours être le plus interne (le plus proche de la définition de la fonction). Une méthode abstraite peut néanmoins contenir une implémentation par défaut qui peut être appelée via super() dans les classes dérivées, offrant ainsi un mécanisme pour du code partagé tout en imposant la redéfinition. Cette approche garantit au moment de la définition de classe que le contrat abstrait est respecté, évitant les erreurs découvertes tardivement à l'exécution.

## 3. Quand utiliser une classe abstraite

Les classes abstraites sont particulièrement utiles lorsque vous concevez une hiérarchie de classes partageant une interface commune mais nécessitant des implémentations spécifiques pour certaines méthodes. Elles sont recommandées quand vous voulez définir un contrat strict que plusieurs classes doivent respecter, garantissant qu'aucune implémentation incomplète ne puisse être instanciée accidentellement. Utilisez-les dans les frameworks et bibliothèques pour définir des points d'extension clairs, dans les architectures en couches pour séparer les interfaces des implémentations, ou lorsque vous voulez factoriser du code commun tout en imposant la spécialisation de comportements spécifiques. Les classes abstraites brillent particulièrement dans les projets d'équipe où elles documentent explicitement les responsabilités et préviennent les oublis d'implémentation. Cependant, évitez-les pour du code simple où le duck typing suffit, ou quand vous n'avez pas réellement de hiérarchie d'héritage justifiée, car elles ajoutent de la complexité et réduisent la flexibilité native de Python.

## 4. Différence avec une interface (dans d'autres langages)

Contrairement aux interfaces pures de Java ou C# qui ne contiennent aucune implémentation et permettent l'héritage multiple sans ambiguïté, les classes abstraites Python peuvent combiner méthodes abstraites ET implémentations concrètes, offrant un modèle hybride plus flexible. En Python, une classe abstraite peut fournir des méthodes utilitaires complètes, des attributs d'instance, et même des implémentations par défaut pour certaines méthodes abstraites, servant à la fois de contrat et de réutilisation de code. De plus, Python supporte naturellement l'héritage multiple, permettant à une classe de dériver de plusieurs classes abstraites simultanément, ce qui compense partiellement l'absence d'interfaces dédiées. Depuis Python 3.8, le concept de Protocol du module typing se rapproche davantage des interfaces traditionnelles avec du structural subtyping (vérification basée sur la structure plutôt que l'héritage), permettant une validation statique optionnelle sans imposer d'héritage explicite. Cette dualité entre classes abstraites (héritage nominal) et protocoles (typage structurel) offre aux développeurs Python le meilleur des deux mondes selon leurs besoins.
