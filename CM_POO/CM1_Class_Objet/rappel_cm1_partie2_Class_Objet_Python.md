# Les 5 concepts clés de la définition de classes en Python

## 1. Définition d'une classe avec `class`

Une classe en Python se définit avec le mot-clé `class` suivi du nom de la classe (par convention en PascalCase/CapWords) et de deux-points, créant un nouveau namespace pour regrouper attributs et méthodes. La syntaxe de base est `class NomClasse:` ou `class NomClasse(ClasseParent):` pour l'héritage, suivie d'un bloc indenté contenant la définition de la classe (docstring, attributs de classe, méthodes). Contrairement à d'autres langages, Python traite les classes comme des objets de première classe : elles peuvent être assignées à des variables, passées en paramètres, et manipulées dynamiquement. La déclaration d'une classe ne crée pas d'instance mais définit un modèle qui sera utilisé lors de l'instanciation via `objet = NomClasse(arguments)`. Le corps de la classe est exécuté immédiatement lors de la définition (au chargement du module), permettant des opérations avancées comme l'enregistrement automatique de sous-classes ou la génération dynamique de méthodes. Par convention, le nom de fichier contenant la classe suit le snake_case (`ma_classe.py`) tandis que le nom de classe utilise le PascalCase (`MaClasse`), facilitant l'import : `from ma_classe import MaClasse`.

## 2. Le constructeur `__init__`

La méthode spéciale `__init__` est l'initialiseur d'instance (souvent appelé constructeur par abus de langage) qui est automatiquement invoquée après la création d'un objet pour initialiser son état interne avec les valeurs fournies lors de l'instanciation. Elle reçoit comme premier paramètre `self` (l'instance nouvellement créée par `__new__`), suivi des arguments passés lors de l'appel `objet = Classe(arg1, arg2)`, et son rôle est de définir les attributs d'instance en assignant `self.attribut = valeur`. Contrairement au vrai constructeur `__new__` (rarement redéfini), `__init__` ne retourne rien (`None` implicitement) car l'objet existe déjà : elle le configure simplement. Cette méthode est optionnelle - une classe sans `__init__` peut être instanciée, héritant du `__init__` de `object` qui ne fait rien. Vous pouvez définir des paramètres avec valeurs par défaut pour rendre certains attributs optionnels (`def __init__(self, nom, age=0):`), ou utiliser `*args` et `**kwargs` pour une flexibilité maximale. Dans les hiérarchies d'héritage, `__init__` de la classe enfant devrait appeler `super().__init__()` pour initialiser correctement la partie parent de l'objet, garantissant une initialisation complète et cohérente de toute la chaîne d'héritage.

## 3. Les attributs d'instance vs attributs de classe

Les **attributs d'instance** sont des variables propres à chaque objet, créées et assignées généralement dans `__init__` via `self.attribut = valeur`, et stockant l'état spécifique de chaque instance. Chaque objet possède sa propre copie indépendante de ces attributs : modifier `objet1.nom` n'affecte pas `objet2.nom`. Ils sont accessibles via `self` à l'intérieur des méthodes et via `objet.attribut` de l'extérieur, et constituent la mémoire personnelle de chaque instance. Les **attributs de classe** sont des variables partagées par toutes les instances d'une classe, définies directement dans le corps de la classe (hors des méthodes), accessibles via `NomClasse.attribut` ou `self.__class__.attribut`. Ils sont utiles pour les constantes communes (`PI = 3.14159`), les compteurs d'instances (`nombre_instances = 0`), ou les valeurs par défaut partagées.

**Attention critique** : la recherche d'attribut en Python suit un ordre précis (instance → classe → parents), créant des pièges subtils. L'assignation `self.attribut = valeur` crée toujours un attribut d'instance, même si un attribut de classe de même nom existe, masquant alors l'attribut de classe pour cette instance seulement. Les attributs de classe mutables (listes, dictionnaires) partagés entre toutes les instances peuvent causer des bugs insidieux si modifiés (`self.liste.append(x)` modifie la liste pour TOUTES les instances), d'où la règle : jamais de valeurs mutables comme attributs de classe par défaut, toujours les initialiser dans `__init__` pour chaque instance individuellement.

## 4. Les méthodes d'instance

Les méthodes d'instance sont des fonctions définies à l'intérieur d'une classe qui opèrent sur les données d'un objet spécifique, recevant obligatoirement `self` comme premier paramètre pour accéder et modifier l'état de l'instance concernée. Elles sont appelées via `objet.methode(arguments)`, Python passant automatiquement l'objet comme premier argument (équivalent à `Classe.methode(objet, arguments)`). Ces méthodes encapsulent les comportements de l'objet, peuvent lire et modifier ses attributs via `self.attribut`, appeler d'autres méthodes via `self.autre_methode()`, et accéder aux attributs de classe via `self.__class__.attribut`. Contrairement aux fonctions normales, les méthodes d'instance créent un lien fort entre données (attributs) et traitements (méthodes), respectant le principe d'encapsulation. 

Par convention, les méthodes publiques utilisent des noms descriptifs en snake_case (`calculer_salaire`, `valider_donnees`), les méthodes protégées sont préfixées d'un underscore (`_methode_interne`) pour signaler qu'elles sont destinées à un usage interne ou par les sous-classes, et les méthodes privées utilisent deux underscores (`__methode_privee`) déclenchant le name mangling pour éviter les conflits dans l'héritage. Les méthodes peuvent retourner des valeurs comme toute fonction Python, ou modifier l'état de l'objet en place (méthodes mutantes), et devraient idéalement faire une seule chose bien (principe de responsabilité unique) pour faciliter les tests et la maintenance.

## 5. `self` : pourquoi et comment ?

`self` est une **convention de nommage** (pas un mot-clé Python) désignant le premier paramètre de toute méthode d'instance, représentant l'instance elle-même sur laquelle la méthode est appelée, permettant d'accéder à ses attributs et méthodes. Bien que vous puissiez techniquement nommer ce paramètre autrement (`this`, `me`, `obj`), utiliser `self` est une convention universelle Python qu'il ne faut jamais violer pour la lisibilité et la cohérence du code. Lorsque vous appelez `objet.methode(arg)`, Python transforme cet appel en `Classe.methode(objet, arg)`, injectant automatiquement l'objet comme premier argument : c'est pourquoi vous définissez `def methode(self, arg):` mais appelez `objet.methode(arg)` sans passer explicitement `self`.

**Pourquoi `self` est nécessaire** : contrairement à certains langages où `this` est implicite, Python rend l'accès à l'instance explicite pour clarifier quand vous accédez à un attribut d'instance (`self.x`) versus une variable locale (`x`), évitant les ambiguïtés. Cette explicité suit la philosophie Python "Explicit is better than implicit" du Zen of Python. Sans `self`, impossible de distinguer `nom` (variable locale ou paramètre) de `self.nom` (attribut d'instance), créant confusion et bugs. 

**Comment utiliser `self`** : dans une méthode, accédez aux attributs via `self.attribut`, modifiez-les via `self.attribut = nouvelle_valeur`, appelez d'autres méthodes via `self.autre_methode()`, et accédez à la classe via `self.__class__` ou `type(self)`. N'oubliez jamais de déclarer `self` comme premier paramètre de toute méthode d'instance, sinon vous obtiendrez une `TypeError` lors de l'appel car Python passera l'instance mais la méthode ne saura pas où la recevoir.
